# 文献雷达：墨刀操作与讲解指南

日期：2026-09-07 | 状态：操作计划，尚未在墨刀执行

本次 Windows 桌面与浏览器操作组件均因沙箱初始化错误未能连接。当前产物是本地 Markdown 文档，没有创建墨刀项目，没有在墨刀导出文件。以下为操作顺序，不是已经验证的当前版本按钮路径。

## 1. 先理解三种产物

- 需求分析回答：谁在什么场景遇到什么问题，为什么值得做。
- PRD 回答：做哪些功能，输入输出是什么，异常怎么处理，怎样判断完成。
- 交互原型回答：页面长什么样，点一个控件之后发生什么。

先写清需求再画页面。墨刀中的可点击原型可以用示例数据，不等于已连接模型和真实检索；运行 Demo 仍在 Streamlit 中。

## 2. 准备项目空间

1. 打开墨刀并进入本人有编辑权限的个人空间。如出现登录，由本人完成。
2. 根据当前界面可用选项新建项目，名称建议“文献雷达｜学生实践 V0.1”。
3. 在项目说明中写明“个人学习 Demo；核心三个模块本人完成，其他部分及文档由 Codex 辅助”。
4. 若当前版本提供文档功能，新建“01 需求分析”和“02 PRD”。若只提供原型编辑，先制作原型，本地 Markdown 保留为正式文字文档，不把长篇 PRD 塞进画布。

不要为了完成这一步购买套餐、安装插件或修改公开分享权限。付费功能不可用时，记录限制，使用现有可用功能。

## 3. 录入需求分析

使用本目录 01_需求分析.md 的内容，按背景、分工、用户与场景、问题、范围、验证计划的顺序分节录入。

每录入一节检查标题层级和表格。如果编辑器不识别 Markdown 表格，可改成“问题 / 需求 / 原因”的短条目，保留信息，不要求照搬语法。

讲解重点：痛点仍是假设，访谈尚未做；先确定一个具体用户任务，不写没有依据的用户规模或效率提升。

## 4. 录入 PRD

使用本目录 02_PRD.md 的内容。先录入目标、范围、流程和页面结构，再录入 F01 至 F05，最后补上验收清单。

讲解重点：需求要写到“别人能照着实现或检查”。例如“检索体验好”无法验收，“未选择来源时禁用提交并提示”可以直接检查。

现有实现与待改进要求必须分开保留，不删除“待执行”“待完善”等状态。

## 5. 建立低保真原型

如可创建网页原型，使用一个常见桌面画布尺寸，例如 1440 × 900；本次只先展示桌面主流程。白底、深色文字、一个强调色即可，先保证结构和状态清楚。

建立以下五个状态页：

| 页面名 | 需要放入的内容 |
| --- | --- |
| 01 研究工作台_空状态 | 左侧研究设置，中间任务输入与快捷任务，右侧暂无来源 |
| 02 研究工作台_加载中 | 保留输入，展示“正在检索并整理来源...” |
| 03 研究工作台_正常结果 | 实际检索词、示例大纲、示例文献、来源入口、导出 |
| 04 研究工作台_部分失败 | 正常结果结构加“部分来源暂不可用”的提示 |
| 05 研究工作台_无结果或失败 | 无结果说明与调整关键词入口；备注全部失败时应使用不同提示 |

原型中的文献条目应明显标“示例数据”，不编造 DOI 或冒充真实论文。引用界面使用“检索并去重；引用待核验”，不要使用“已核验”标签。

在原型里把真实网址跳转、文件导出等未接通的动作记为“仅模拟”。不要让预览者以为按钮已经完成真实检索。

## 6. 连接交互

1. 空状态“提交任务”连接到加载页。
2. 若支持延时跳转，加载页连接正常结果页，并在页面备注写“原型模拟”；否则使用原型预览的页面切换演示。
3. 结果页“新建研究”连接空状态。
4. 无结果页“修改主题”连接空状态。
5. 部分失败作为独立异常分支，用预览页面列表演示，不给产品增加一个不必要的“制造失败”按钮。

状态页共用相同布局和控件位置，减少跳转时视觉变化。

## 7. 预览和验收

从空状态开始完整点一遍，检查文字是否被截断、是否可以回到输入页、异常原因是否清楚。逐条对照 PRD，不能因为页面画出来就勾选代码验收通过。

确认平台显示保存成功，再根据实际可用功能导出文档或原型预览。导出后打开检查标题、表格和分页。公开分享或发送给面试官应按本人意愿另行操作。

## 8. 适合面试的讲解顺序

先展示需求分析中的目标用户和任务，再展示一次原型操作，然后展示 PRD 中的一个功能与异常分支，最后运行真实 Demo 并说明个人分工。

可以这样讲：“我从学生查文献的场景做了一个小范围 Demo。Agent、工具封装和 MCP 服务是我自己完成的，其他部分借助 Codex。产品文档也是在辅助下整理的；目前用户需求还需要试用验证，我重点练习的是把问题写成具体规则，并用验收清单检查。”
