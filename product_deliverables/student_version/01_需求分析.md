# 文献雷达：需求分析

版本：学生实践版 V0.1 | 日期：2026-09-07 | 项目阶段：个人 Demo

## 1. 项目背景

我是一名计算机类专业的大四学生。学习了大模型、Agent 编排和 MCP 等基础知识后，希望围绕论文资料查找做一个可以运行的小工具，并练习需求分析和产品文档写作。

文献雷达面向论文写作的大学生和初级专题研究者，帮助用户从研究主题出发，得到文献清单、原文入口和研究大纲。

本文是结合现有 Demo 整理的需求分析草稿。痛点目前来自选题假设和项目实践，尚未通过正式用户访谈确认；没有真实用户量、留存或节省时间的数据。

## 3. 目标用户与使用场景

第一版优先面向需要做课程论文或毕业论文开题、尚不熟悉文献检索的学生。初级专题研究者是次要目标用户，暂不扩展复杂的团队协作需求。

示例场景（用于设计，不是真实访谈记录）：一名学生准备研究“生成式 AI 对大学生写作的影响”，需要先找到近几年的相关文献，再整理一个能继续阅读和修改的大纲。

一次任务的目标：输入主题和年份范围后，获得可打开来源的文献清单，并知道哪些内容仍需阅读全文确认。

## 4. 从问题到需求

| 假设中的问题 | 需要进一步了解什么 | 第一版应提供什么 |
| --- | --- | --- |
| 选题较宽，不知道用什么词搜 | 用户是否真的在检索词上花费较多时间 | 模型组织检索词，并展示实际检索词 |
| 多个平台的结果分散、重复 | 用户目前怎样整理重复文献 | 统一展示文献信息，按 DOI 和标题规则去重 |
| AI 给出的参考文献不容易核实 | 用户如何判断引用是否存在 | 返回真实检索来源、稳定编号和原文入口 |
| 有了文献仍难形成阅读结构 | 用户是否需要初步大纲、需要多详细 | 基于检索结果生成大纲，标明证据边界 |

优先解决“找到资料并回查来源”。自动大纲的价值仍需用户试用确认，不能把生成成功直接等同于对论文有帮助。

## 5. 对现有方法的初步理解

以下是方案层面的初步比较，不代表完成了正式竞品调研。

| 方法 | 适合做什么 | 本项目希望补充的环节 |
| --- | --- | --- |
| 直接使用通用 AI 对话 | 讨论选题、整理表达；有些产品也支持联网检索 | 让本 Demo 的文献清单与检索来源对应，便于回查 |
| 直接查询学术数据库 | 查找和筛选文献 | 将多个来源结果统一展示，减少重复整理 |
| Zotero 等文献管理工具 | 收藏、管理和组织已找到的文献 | 聚焦更前面的主题摸底与初步大纲 |

文献雷达不是学术数据库或文献管理器的替代品。第一版只验证一段小流程是否对学生有用。

## 6. 第一版范围与取舍

P0 表示完成主要任务必须具备，P1 表示主要流程可用后再考虑。

| 优先级 | 功能 | 理由 |
| --- | --- | --- |
| P0 | 主题、年份、数量和来源设置 | 限定检索范围 |
| P0 | 检索、去重、文献清单和来源入口 | 完成资料查找与回查 |
| P0 | 带来源编号的大纲和证据提示 | 组织阅读思路，提醒核实 |
| P0 | 失败说明和单源失败时返回其他结果 | 避免用户把不完整结果当成完整检索 |
| P1 | 多轮追问、Markdown 导出 | 方便继续研究；现有 Demo 已实现 |
| P1 | 历史记录、PDF 全文检索 | 复杂度更高，暂缓 |

优先级表示对核心任务的重要程度，不表示实现先后或是否已实现。暂不做论文代写、模型训练、付费墙绕过、多人协作和运营看板。学习过 RAG，不代表当前 Demo 已有 PDF 向量检索。

## 7. 已知问题与证据

项目保存的 2026-09-04 检索基准包含 5 个主题：全部得到结果，平均 7.4 篇，共去除 3 条重复；但 arXiv 在这 5 次测试中全部失败，结果来自 Crossref。检索中位耗时约 21.6 秒，平均摘要覆盖率约 49.7%。

这些是既有的小样本检索记录，本次没有重跑；不包含完整模型生成耗时，也不能证明长期稳定性、检索相关性或用户效率提升。

此外，当前引用限制主要靠提示词，没有独立的程序化引用校验器。有 DOI 或来源编号不等于大纲论点已经被论文证实。

## 8. 下一步如何验证

计划邀请 3 至 5 位有课程论文或开题需求的同学试用，尚未执行。先了解他们最近一次真实查文献经历，再让他们独立完成任务。

访谈问题：

1. 最近一次查文献是为了什么作业或研究？
2. 当时用了哪些工具？请按顺序描述操作过程。
3. 哪一步最费时间？能举一个具体例子吗？
4. 你怎样判断一条参考文献是否真实、是否相关？
5. 得到文献后，通常怎样整理和继续阅读？

试用任务：输入一个自己的研究主题，找到两篇认为相关的文献，打开来源，再导出或说明下一步想做什么。

人工记录：是否完成、在哪一步需要帮助、两篇文献为什么相关或不相关、是否理解摘要与全文的区别、等待是否可以接受。计时用于观察问题，不直接宣称提升百分比。

如果多数同学卡在输入主题，先改输入提示；如果能操作但结果不相关，先改检索；如果把大纲当成已核实结论，先改证据提示与引用校验。试用后再调整范围。
