# 文献雷达：产品需求文档（PRD）

版本：学生实践版 V0.1 | 日期：2026-09-07 | 状态：供本人审阅的草稿

## 1. 文档目的

把“帮助学生找文献”写成具体的输入、操作、输出和验收条件，作为个人 Demo 的复盘及下一步改进依据。已有实现按代码核对，尚未实现的要求明确标注；本次不修改应用代码，也未重新做运行验收。

个人分工：本人完成 agent.py、tools.py、mcp_server.py；底层检索与去重、页面、测试等借助 Codex 完成；本次文档也由 Codex 辅助整理。

## 2. 产品目标和范围

目标用户：准备课程论文、毕业论文开题的大学生，以及初级专题研究者。

目标任务：输入研究主题后，得到去重文献清单、原文入口和带来源编号的初步研究大纲。

第一版不承诺：论文全文阅读、结论准确性自动核验、完整中文数据库覆盖、正式论文代写、重启后保留全部历史。

## 3. 用户流程

填写研究主题和设置 → 提交任务 → 等待检索和整理 → 查看文献与大纲 → 打开来源核实 → 继续追问或导出。

异常分支：没有选择来源时阻止提交；部分来源失败时保留成功结果并提示；全部失败或无结果时说明原因并引导调整后重试。后两种情况的专用状态页面需要完善。

## 4. 页面结构

一个研究工作台即可，不做复杂后台。

| 区域 | 内容 | 主要操作 |
| --- | --- | --- |
| 左侧设置 | 主题、关注重点、起始年份、文献数量、数据源 | 修改设置、新建研究、导出记录 |
| 中间研究区 | 输入框、任务状态、对话和大纲 | 提交任务、继续追问 |
| 右侧来源区 | 文献编号、标题、作者、年份、期刊或平台 | 打开原文 |

墨刀原型规划为同一工作台的 5 个状态页：空状态、加载中、正常结果、部分来源失败、无结果或全部失败。它们是流程演示页，不代表后台已经实现所有状态。

## 5. 功能需求与验收

### F01 输入研究任务（P0）

现状：已实现基本输入和设置。

- 研究主题可在侧栏填写；未填写时使用聊天任务作为主题。关注重点可选。
- 起始年份范围为 1900 至当前年份，默认值按现有代码为当前年份减 5 与 2020 的较大值。
- 文献数量为 4 至 12，默认 8；含义是期望上限，不能保证一定返回足量。
- 默认选中 Crossref 和 arXiv，至少保留一个来源。
- 没有数据源时显示“请至少保留一个数据源”，禁用任务输入和快捷任务。

待改进：没有明确研究主题时点击快捷任务，应提示补充主题；现有页面没有专门拦截这个情况。年份、数量等设置目前通过提示词传给模型，仍需验证模型是否正确传入工具，不能视为完全由程序强制保证。

验收：取消全部来源后无法提交；恢复一个来源后可以提交。输入具体主题和设置后，检查实际工具参数是否一致。

### F02 检索和去重（P0）

现状：已实现公开接口检索和确定性去重，接口稳定性仍需改进。

- Agent 调用检索工具，返回标题、作者、年份、摘要、DOI、原文入口等可获得字段。
- 两条记录都有 DOI 时，按规范化 DOI 是否相同判断重复；至少一条没有 DOI 时，再按规范化标题及相似度判断，当前阈值为 0.94。
- 合并重复记录时补充较完整字段，并保留来源信息。
- 实际返回可能少于设置数量；显示返回数量和去重数量。
- 单个来源请求失败时，继续处理其他来源并返回警告。没有做自动重试和缓存。

验收：相同 DOI 的两条记录合并；不同 DOI 不因标题相似被合并；缺 DOI 的高度相似标题按规则处理；模拟一个接口失败，另一个仍能返回结果与警告。

### F03 文献与大纲（P0）

现状：已实现模型生成和来源展示；引用正确性尚无程序校验。

- 回答包含检索说明、文献清单、初步研究大纲和证据边界。
- 系统提示词要求只引用工具返回的来源编号，编号用于回查文献。
- 来源区展示编号、标题、作者、年份、期刊或平台；有链接时提供“打开原文”。
- 缺失信息如实标为未提供，不要求模型补齐未知事实。

待改进：来源区“本轮已核对并去重”容易被理解为内容已经核验，建议改为“本轮检索并去重；引用待核验”。在回答后增加程序校验，检查编号是否存在；即使编号有效，仍需人工判断论点是否被原文支持。

验收：人工逐项比对一次生成结果的引用编号与来源；打开至少两条链接，核对标题。没有摘要的来源不能被描述成已阅读全文。验收失败记录为缺陷，不把提示词约束当作通过证明。

### F04 状态与异常（P0）

| 状态 | 当前实现 | 目标表现 / 验收点 |
| --- | --- | --- |
| 空状态 | 显示暂无记录、快捷任务和暂无来源 | 用户知道从哪里输入任务 |
| 加载中 | 显示“正在检索并整理来源...” | 状态可见；不显示没有依据的完成百分比 |
| 正常结果 | 显示答案、来源和统计 | 显示实际结果数，不用空记录补足数量 |
| 部分来源失败 | 显示工具警告并保留其他结果 | 提示“部分来源暂不可用，以下为已获取结果”，明确失败来源 |
| 全部来源失败 | 工具可返回零条和警告，缺少独立界面分支 | 待完善：说明服务暂不可用，引导重试，不展示成功状态 |
| 检索无匹配结果 | 缺少与接口失败区分的独立界面分支 | 待完善：提示修改关键词或年份范围，不编造参考文献 |
| 模型或执行异常 | 显示执行失败及异常信息 | 待完善：面向用户说明失败，技术细节留给调试 |

验收：分别模拟部分失败、全部失败、正常返回零条及模型异常，检查是否被区分。上述待完善项尚未完成，不能直接勾选通过。

### F05 追问和导出（P1，现有 Demo 已实现）

- 在同一会话中继续追问，使用进程内消息记忆。服务重启后的历史不保证保留。
- 来源区主要展示本轮检索来源；未重新检索时的展示需在运行中核对，不承诺自动汇总完整历史来源。
- “新建研究”重置当前会话。
- Markdown 导出包含对话中的问题与回答，不是论文全文或完整的结构化来源数据库。
- 没有消息时导出按钮不可用；已有消息时可以导出，不代表必须成功检索才可导出。

验收：连续提问两轮，检查上下文；导出并检查两轮文本；新建研究后检查旧对话是否清空。

## 6. 实现方式（便于讲解）

Streamlit 页面收集输入 → LangGraph Agent 判断工具调用 → tools.py 调用底层检索 → 返回结构化文献 → 模型整理回答 → 页面展示。

mcp_server.py 把同一检索能力提供给其他 MCP 客户端，是复用接口，不是普通学生使用网页时必须操作的步骤。当前不需要多 Agent，也未实现 PDF 向量检索。

## 8. 已知限制

公开接口可能失败或限流；中文资料覆盖有限；摘要可能缺失；标题去重可能误合并；模型可能引用错误；来源链接可能需要机构权限。Demo 展示时应说明这些限制，最终论文引用需要本人打开原文确认。
